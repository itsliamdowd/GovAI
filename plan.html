Council records: full minutes archive (2015→) + YouTube caption transcripts; strict-schema fix

in-progress

Goal. User asked whether every council meeting's transcript is stored. Answer was no (30 recent meetings, agendas+minutes only). This entry widens coverage to everything that is actually obtainable and adds real spoken-word transcripts where they exist.

Files

  • transcripts.js (new) — yt-dlp lists the City of Santa Monica YouTube channel (UC4V0jOEL4JMCcElkGA7AJpA), keeps council meeting videos (filters out candidate forums, COVID PSAs, retreats), parses the meeting date from the title (handles "Sept.", ordinals like "28th"), dedupes to one video per date (prefers "(with captions)", drops "Copy of"), downloads the English caption track (manual else auto), flattens rolling VTT cues to {t, text}, chunks ~1500 chars with a timestamped watch?v=…&t=Ns link. Cached per video in data/transcripts/*.json.
  • council.js — COUNCIL_MEETINGS default 30 → 1000 (all past meetings in the Agendas & Minutes dataset, 2015→).
  • rag.js — searchCouncil(query, k, year, doc) gains a doc filter; with no filter it returns half official-record hits (agenda/minutes) and half transcript hits so bulkier transcripts don't crowd out votes.
  • server.js — runs ingestTranscripts in the background alongside ingestCouncil; search_council_meetings tool gains doc: ""|"agenda"|"minutes"|"transcript"; prompt explains when to use which and that transcripts are auto-captions. Bug fix: removed minimum/maximum from the strict query_dataset.limit integer schema (API 400: "For 'integer' type, properties maximum, minimum are not supported"); runtime clamp in rag.js already covers it.
  • warm.js (new) — one-off cache warm-up (node warm.js) so a server restart doesn't re-fetch ~440 PDFs.
  • test.js — date parsing, VTT dedupe, timestamped chunk links, doc filter isolation.
  • System dep: yt-dlp installed via Homebrew (2026.08.19). pdftotext (poppler) already present.

Voice mode: ChatGPT-style full-screen voice conversation

done

Goal. User: "microphone should be like the gpt voice talk feature and look like it". Tapping 🎤 now opens a full-screen voice overlay instead of dictating into the textarea: a large glowing orb that swells with mic level while listening, morphs while thinking, pulses while the reply is spoken aloud. Hands-free loop: listen → send → speak reply → listen again, until the user taps ✕. Mute button pauses listening.

Files

  • public/index.html — new .voice overlay CSS + markup (#voice, #orb, #vstate, #vtext, #vmute, #vend); form.onsubmit body extracted into send(text) which returns the bot bubble so voice mode can read its plain textContent for TTS; voice block replaces the old inline SpeechRecognition snippet.

Approach

  • STT: native SpeechRecognition (hidden if unsupported, as before). TTS: native speechSynthesis. Orb level: getUserMedia + AnalyserNode RMS → transform:scale(). No dependencies, no server change.
  • States live on #voice[data-state] = listening | thinking | speaking; CSS keys animations off it.

Verify. Inline script extracted and passes node --check. Browser check pending by user (Chrome MCP still locked by another session). Known limits: TTS uses the OS default voice; recognition quality depends on the browser's engine (Chrome/Safari); muting mid-reply lets the reply finish, then shows "Muted".

Santa Monica city assistant: RAG chat + open data + council records + permit intake

done

Goal. america.gov-style single front door for a city: a chatbot that knows Santa Monica city services, pulls live rows from data.santamonica.gov, searches City Council agendas and official minutes, and files permit applications / 311 requests end to end. Mobile-first PWA.

Files

  • server.js — Node http server, SSE streaming to browser. Claude claude-opus-5-5 via @anthropic-ai/sdk (client.beta.messages.stream, fallbacks: "default", cached system prompt, effort medium). Manual streaming tool loop (pause_turn / refusal / tool_use handled). Tools: search_city_knowledge, query_dataset, search_council_meetings, web_search_20260209 (allowed_domains = santamonica.gov family), submit_application, check_application_status. Sessions in-memory; applications in data/applications.json.
  • rag.js — BM25 index (no embeddings dependency) over knowledge/*.md chunks + CKAN catalog (82 datasets: title, notes, tags, datastore field names; cached 24h in data/catalog.json). queryDataset() → CKAN datastore_search live (full-text q, filters, sort). addDocs() rebuilds index; searchCouncil() filters to council docs.
  • council.js — reads City Council rows from the "Agendas & Minutes" dataset (resource 40013cb9…, 450 council meetings incl. future), ingests the 30 most recent past meetings: agenda text from IQM2 HTML, minutes via pdftotext (poppler). Cached per meeting in data/council/*.json; chunked ~1500 chars; runs in background after server start. Returns upcoming meeting dates too.
  • knowledge/permits-howto.md, housing-rent-control.md, transportation-parking.md, public-safety-code.md, city-services-az.md — 43 KB of sourced sections (each ends with Source: <santamonica.gov url>) written by a research subagent; auto-indexed because rag.js globs knowledge/*.md.
  • knowledge/santa-monica.md — hand-compiled KB (contacts, 311, departments, permit types & where they live, trash, parking rates FY26-27, housing, places), sourced from santamonica.gov searches 2026-10-17.
  • public/index.html, manifest.webmanifest, icon.svg — single-page PWA: safe-area insets, sticky blurred composer, dark mode, quick-action tiles, streaming markdown (marked + DOMPurify from cdnjs), status line for tool calls, dataset/minutes source chips, application confirmation card with copy, "My applications" bottom sheet (localStorage), Web Speech voice input.
  • test.js — store round-trip, retrieval, council chunking, council/general index isolation. npm test passes.
  • package.json, .env.example, .gitignore, README.md.

Decisions

  • API key: per-project .env loaded by node --env-file=.env (native, no dotenv). User supplies key.
  • RAG without embeddings: BM25 in-process over ~1k docs. ponytail: swap to vector store if corpus grows past RAM.
  • Council "transcripts": Granicus/IQM2 video player exposes no caption file and video_url is empty in the dataset, so official minutes PDFs are the record of what was said/decided. Agenda HTML gives item text + recommended actions.
  • Open data portal contains fuzz rows (pHqghUme, ncMUFCMU) in several datasets; prompt tells the model to cite dataset + URL and the UI shows source chips so users can check.
  • datastore_search_sql is blocked by the portal's WAF for complex queries; use datastore_search with filters.

Review fixes (from code-review subagent)

  • server.js withSessionLock() — per-session promise chain so two concurrent sends on one sessionId can't interleave the shared messages array. Verified with two parallel POSTs.
  • server.js error path — history rolls back to before the failed user turn (findLastIndex + splice) instead of popping only a trailing user message.
  • server.js static handler — path.resolve + prefix check against public/. Reviewer's traversal claim was incorrect (path.join doesn't treat a leading slash as absolute) but the guard is one line; /../, //etc/hosts, %2e%2e all 404.
  • council.js chunk() — oversize paragraphs now split on whitespace instead of mid-word. rag.js logs per-resource field-fetch failures.
  • Declined: extra tool-name guard, filters JSON pre-validation, localStorage warning — all already surface as is_error/caught paths; not worth code.

UI QA (Chrome MCP subagent, 1280×900 and 390×844, light + dark)

  • No console errors, no horizontal scroll on phone, composer pinned, tiles 2-col on phone / 3-col desktop, sheet + copy card work. Fixed: added <meta name="mobile-web-app-capable"> next to the Apple one.

Verified

  • npm test passes (store, retrieval, council chunking, index isolation). Server boots: 82 datasets indexed, 30 council meetings → 789 chunks in background. /chat with a bad key streams a clean error event.
  • Not verified in-session: a real model round-trip — needs the user's ANTHROPIC_API_KEY in .env.
