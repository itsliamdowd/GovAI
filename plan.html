Daily watch alerts: "track this address" → judge model → email on change

in-progress

Goal. User: residents can say "let's track a specific address" (or any topic). The assistant creates an alert; a daily job gathers what the RAG index (knowledge + council agendas/minutes/transcripts) and data.santamonica.gov datasets currently say about it, diffs against what was already seen, asks a decision ("judge") model has something changed for this query? yes/no, and if yes compiles and sends an email. If no, nothing happens.

Assumption. "Jev as a decision model" read as an LLM-as-judge step; implemented as JUDGE_MODEL env (default claude-haiku-5-5, cheap yes/no) with a forced decide tool returning {changed, reason, subject, body}.

Files

  • alerts.js (new) — createAlert(rag, input) (snapshots baseline evidence keys so day 1 only reports new things), cancelAlert, gatherEvidence(rag, topic) (council excerpts + knowledge chunks + rows from the top 3 matching datastore resources via queryDataset(q=topic)), pure diffEvidence(seenKeys, items), judge(), sendEmail() (Resend HTTP API when RESEND_API_KEY set, else writes data/outbox/*.txt), runAlerts(rag). Store: data/alerts.json.
  • server.js — tools create_alert / cancel_alert; SYSTEM prompt paragraph on when to offer a watch; refreshCouncil() factored out of startup so the daily job re-ingests new agendas/minutes/transcripts before checking; scheduleDaily() fires at ALERT_HOUR (default 07:00 local) every 24h; POST /api/alerts/run triggers a run now (demo/cron hook); SSE event {type:"alert"}.
  • rag.js — addDocs dedupes by url#part so daily re-ingest doesn't duplicate council chunks.
  • public/index.html — handles the alert event: card "Daily watch on", and the alert appears in the My applications sheet with status watching.
  • test.js — createAlert round-trip + diffEvidence check (no API call).
  • .env.example, README.md — JUDGE_MODEL, ALERT_HOUR, RESEND_API_KEY, ALERT_FROM.

Flow

chat: "track 1685 Main St" → ask email → create_alert{topic,address,email}
       → baseline = keys(gatherEvidence)            (stored, nothing sent)
daily 07:00 → refreshCouncil() → for each alert:
       fresh = diffEvidence(alert.seen, gatherEvidence(topic))
       none → skip (no email)
       some → judge(topic, fresh) → {changed:false} → mark seen, no email
                                  → {changed:true,subject,body} → sendEmail → mark seen

Acceptance

  • npm test passes; alert created via chat shows card + sheet entry; curl -X POST :8787/api/alerts/run returns per-alert {id, new, changed}; email lands in data/outbox/ without Resend configured.

Cited council video moments are cached and playable in the app

in-progress

Goal. When an answer cites a council video at a timestamp, that exact moment is stored server-side and shown to the resident as a playable clip they can save and come back to.

Files

  • transcripts.js — citedMoments(text) extracts every youtube.com/watch?v=ID&t=Ns link (handles &amp;, dedupes). clipWindow(videoId, t) reads the cached transcript and returns the −10s/+90s window as text plus url, embed (youtube-nocookie, start=), hms, meeting date. Video id validated against ^[\w-]{6,20}$ so it can't become a path.
  • server.js — after the final assistant text of a turn, saveClipsFor(text) persists each cited moment to data/clips.json (keyed VIDEO-SECONDS, with cited_at) and streams a clips SSE event. Routes: GET /api/clips (newest first), GET /api/clips/:id. Prompt now tells the model to include the exact transcript excerpt url when quoting a meeting.
  • public/index.html — clipCard(): thumbnail with timestamp badge → click swaps in the embedded player at that second; excerpt (expandable), "Save moment", "Open on YouTube". Sheet renamed "My stuff": Applications + Saved council moments (localStorage sm_moments); tapping a saved moment re-renders the clip and autoplays.
  • test.js — citation parsing incl. dedupe/entity-escaped ampersand; path-injection guard on clipWindow.
  • transcripts.js — listVideos() now walks /streams and /videos (council meetings are livestreams). Caption pull for ~248 streams re-running via node warm.js; per-video JSON cache means already-fetched videos are skipped.

Design notes

  • "Cache" = the transcript window text + metadata in data/clips.json; the full caption JSON per video already lives in data/transcripts/. We don't download video. The embed loads only on tap (thumbnail first) so answers with several citations stay light on phones.
  • Moments are detected from the model's final text, not from the tool results, so only what the answer actually cites becomes a clip.

Chat "Thinking… forever" fixed: Opus is rate-capped in this workspace; default to Sonnet, no silent retries, cache dataset rows

done

Symptom. Every chat hung on "Thinking…" with zero SSE events for 110+ s, then (if at all) the whole answer appeared at once. Retrieval was not the cause: BM25 is in-RAM and the server answered static requests in <1 ms during the hang.

Root cause (measured with a throwaway SDK probe, since deleted). claude-opus-5-5 returns 429 rate_limit_error: "would exceed the rate limit you configured in workspace Hackathon of 1 input tokens per minute" on every call. The SDK's default maxRetries: 2 honours retry-after and sleeps up to 60 s per retry with no events, so the browser saw nothing for ~2 min. claude-haiku-5-5 and claude-sonnet-5-5 answer in 0.7–1.0 s, and streaming via messages.stream delivers tokens incrementally (first event at 0.6 s). models.list and base URL are normal; no proxy env.

Files

  • server.js — MODEL = process.env.MODEL || "claude-sonnet-5-5" (comment explains the Opus cap and how to lift it); stream call takes { maxRetries: 0, timeout: 120000 } so a 429/529 reaches the existing error handler ("Rate limited, try again in a moment.") in under a second instead of hanging.
  • rag.js — queryDataset() memoises CKAN datastore_search results in a Map keyed by the exact params, 10-min TTL (ponytail: unbounded; LRU/KV if it grows). Repeated demo questions skip the 0.3–15 s network hop.

Streaming (user asked for tokens to appear as generated)

Already true end to end: server forwards each text delta as an SSE frame; public/index.html send() reads the body with getReader() and re-renders the bubble per frame (index.html:246-249). The "all at once" look was the retry stall. No frontend change.

To use Opus again

console.anthropic.com → workspace Hackathon → Limits → raise the per-model input-tokens-per-minute for claude-opus-5-5, then add MODEL=claude-opus-5-5 to .env and restart.

Verified (curl -N against the restarted server). Fresh session "hi": first token at 2.0 s, then word-by-word. Warm session dataset question: search_city_knowledge status at 1.6 s, query_dataset at 3.8 s, first text at 5.7 s, deltas every ~5 ms. Very first request after boot took 22 s to its first frame (prompt-cache write + cold path); later requests are 2–6 s. Row cache was not exercised by the model's query sequence (each call used different params); logic is a 4-line memo, covered by inspection.

Santa Monica city assistant: RAG chat + open data + council records + permit intake

done

Goal. america.gov-style single front door for a city: a chatbot that knows Santa Monica city services, pulls live rows from data.santamonica.gov, searches City Council agendas and official minutes, and files permit applications / 311 requests end to end. Mobile-first PWA.

Files

  • server.js — Node http server, SSE streaming to browser. Claude claude-opus-5-5 via @anthropic-ai/sdk (client.beta.messages.stream, fallbacks: "default", cached system prompt, effort medium). Manual streaming tool loop (pause_turn / refusal / tool_use handled). Tools: search_city_knowledge, query_dataset, search_council_meetings, web_search_20260209 (allowed_domains = santamonica.gov family), submit_application, check_application_status. Sessions in-memory; applications in data/applications.json.
  • rag.js — BM25 index (no embeddings dependency) over knowledge/*.md chunks + CKAN catalog (82 datasets: title, notes, tags, datastore field names; cached 24h in data/catalog.json). queryDataset() → CKAN datastore_search live (full-text q, filters, sort). addDocs() rebuilds index; searchCouncil() filters to council docs.
  • council.js — reads City Council rows from the "Agendas & Minutes" dataset (resource 40013cb9…, 450 council meetings incl. future), ingests the 30 most recent past meetings: agenda text from IQM2 HTML, minutes via pdftotext (poppler). Cached per meeting in data/council/*.json; chunked ~1500 chars; runs in background after server start. Returns upcoming meeting dates too.
  • knowledge/permits-howto.md, housing-rent-control.md, transportation-parking.md, public-safety-code.md, city-services-az.md — 43 KB of sourced sections (each ends with Source: <santamonica.gov url>) written by a research subagent; auto-indexed because rag.js globs knowledge/*.md.
  • knowledge/santa-monica.md — hand-compiled KB (contacts, 311, departments, permit types & where they live, trash, parking rates FY26-27, housing, places), sourced from santamonica.gov searches 2026-10-17.
  • public/index.html, manifest.webmanifest, icon.svg — single-page PWA: safe-area insets, sticky blurred composer, dark mode, quick-action tiles, streaming markdown (marked + DOMPurify from cdnjs), status line for tool calls, dataset/minutes source chips, application confirmation card with copy, "My applications" bottom sheet (localStorage), Web Speech voice input.
  • test.js — store round-trip, retrieval, council chunking, council/general index isolation. npm test passes.
  • package.json, .env.example, .gitignore, README.md.

Decisions

  • API key: per-project .env loaded by node --env-file=.env (native, no dotenv). User supplies key.
  • RAG without embeddings: BM25 in-process over ~1k docs. ponytail: swap to vector store if corpus grows past RAM.
  • Council "transcripts": Granicus/IQM2 video player exposes no caption file and video_url is empty in the dataset, so official minutes PDFs are the record of what was said/decided. Agenda HTML gives item text + recommended actions.
  • Open data portal contains fuzz rows (pHqghUme, ncMUFCMU) in several datasets; prompt tells the model to cite dataset + URL and the UI shows source chips so users can check.
  • datastore_search_sql is blocked by the portal's WAF for complex queries; use datastore_search with filters.

  • server.js error path — history rolls back to before the failed user turn (findLastIndex + splice) instead of popping only a trailing user message.
  • server.js static handler — path.resolve + prefix check against public/. Reviewer's traversal claim was incorrect (path.join doesn't treat a leading slash as absolute) but the guard is one line; /../, //etc/hosts, %2e%2e all 404.

  • Declined: extra tool-name guard, filters JSON pre-validation, localStorage warning — all already surface as is_error/caught paths; not worth code.
